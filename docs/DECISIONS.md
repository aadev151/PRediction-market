# Decisions

One line per non-trivial choice: what we decided and why. Append only. Newest at the bottom.

| # | When | Decision | Why |
|---|---|---|---|
| 1 | 2026-11-07 12:00 | Build a **standalone, target-agnostic factory**; drop PLAN_V0's Crossroads app. | Software Factory is judged on "built to run again next month on a different problem". A `.prm.toml` plugs in any repo. |
| 2 | 2026-11-07 12:00 | **LMSR** market maker, `b = 20`, start price 0.50, per-trader cap `min(25% bankroll, 30)`. | Closed-form prices, bounded maker loss (≤ b·ln2), and 0.50→0.90 costs b·ln5 ≈ 32.2 > 30, so no single trader can force an auto-merge. |
| 3 | 2026-11-07 12:00 | `.prm.toml` is read from the PR's **base** sha, never the head. | A PR must not be able to rewrite its own gate or settle command. |
| 4 | 2026-11-07 12:00 | **Fail closed**: any error or < 2 responding traders → VOID, refund, gate `failure`. | An engineer only trusts a gate that can't fail open into a merge. |
| 5 | 2026-11-07 12:00 | Ground truth is the **settlement outcome**, not the mutation label; settle every market, auto-merged ones included. | Skipping settled-by-merge markets would bias calibration. Label/outcome mismatches reveal holdout gaps. |
| 6 | 2026-11-07 12:00 | Agents only emit `{p_yes, rationale, key_risks}`; deterministic code owns trading, gating, settlement and transitions. | "Agents are suggestions, states are laws." Keeps every decision auditable and testable. |
| 7 | 2026-11-07 12:20 | Python 3.12 via `uv`, hatchling build backend, ruff + pytest; pytest `--import-mode=importlib` with `testpaths = ["tests"]`. | macOS system python is 3.9. importlib mode lets `tests/` mirror `prm/` without basename clashes; `testpaths` keeps pytest from collecting the sample target's tests or fixture holdouts. |
| 8 | 2026-11-07 12:20 | The **no-solo-auto-merge invariant is enforced at config load**: `ServerConfig` and `gate_for(overrides)` reject any market/gate config where one trader's `max_spend_abs` can move `initial_price` to `auto_merge` (or where markets would open at/above it). | R-MKT-3 holds for every configuration, not just the defaults. Consequence: a repo can't lower `auto_merge` below ~0.87 with default market params. |
| 9 | 2026-11-07 12:20 | Remote `.prm.toml` (from GitHub) may **not** use `holdouts_path`; only local targets can (`parse_target_config(..., allow_holdouts_path=False)` by default). | A local path in a remote config would let any registered repo point the factory at arbitrary files on the server. |
| 10 | 2026-11-07 12:20 | Commands are `shlex.split` **first**, then placeholders are filled per token; only `{head} {holdouts} {junit} {tmp}` (+ `{findings}` for red team) are allowed, plain names only. | Paths with spaces stay one argument, substituted values are never re-parsed, and nothing goes through a shell. Typos fail at load instead of at settlement. |
| 11 | 2026-11-07 12:20 | `.prm.toml` must set **exactly one** of `holdouts_repo` / `holdouts_path`; `spec` must be a relative in-repo path; `HOME`/`TMPDIR` can't be overridden in `settle.env`; red-team commands must write to `{findings}`; configs over 64 KB are rejected. | Unambiguous, and keeps a target config from escaping the sandbox's isolation or reading outside its tree. |
| 12 | 2026-11-07 12:20 | Shared dataclasses validate fail-closed rules in `__post_init__`: an abstaining belief must carry an error; a `GateDecision` without a price must be `failure`; `SettlementResult.outcome is None` exactly when `error` is set. | Makes "a missing number silently becomes a merge" unrepresentable. |
| 13 | 2026-11-07 12:20 | Trader roster names are typed as the four roles (`diff_reader`, `coverage`, `security`, `skeptic`); evolution (P2) lineage names like `security.g2` live in the DB, not the config. | A misspelled role fails at load instead of silently getting no evidence slice. |
| 14 | 2026-11-07 12:20 | Ruff excludes `*.md`. | Ruff's formatter reformatted the Python snippets inside PLAN.md; the docs are hand-written specs and must not change under a formatter. |
| 15 | 2026-11-07 12:45 | Repo rules are **enforced, not just documented**: `.githooks/` (pre-commit/pre-push refuse main), a Claude Code PreToolUse hook (`scripts/git_guard.py`) that also blocks `--no-verify` and `core.hooksPath` changes, a Stop hook (`scripts/tldr_check.py`) requiring the TL;DR after any commit/push, and GitHub branch protection on `main`. | "Rules in CLAUDE.md are suggestions; hooks are laws." Three layers so neither a human slip nor an agent can land on main directly. |
| 16 | 2026-11-07 13:10 | **semgrep is CI-only**, not a `pyproject` dependency; CI installs a pinned version (`semgrep==1.184.0`) into its own venv under `$RUNNER_TEMP`. | Its large dependency tree (mcp, opentelemetry, ...) had open CVEs that would fail `pip-audit` on the product's environment; isolating it keeps the audit about what we ship. Pinned so registry runs are reproducible. |
| 17 | 2026-11-07 13:10 | CI actions are pinned to **full commit SHAs** (release in a comment), not `@v4`-style tags. | The registry rule `github-actions-mutable-action-tag` (p/owasp via semgrep) flagged the tags; SHA pinning is the real fix for tag-repointing supply-chain attacks, so no suppression needed. |
| 18 | 2026-11-07 13:10 | Semgrep rule tests live in `.semgrep/tests/` and run per file (`semgrep --test --config .semgrep/rules.yml <file>`); `.semgrepignore` restates semgrep's defaults (incl. `tests/`, `.semgrep/`) so the deliberate violations never hit the `--error` scan. Fixtures carry `# ruff: noqa`. | semgrep 1.184's `--test` crashes when given a config file plus a target directory; a custom `.semgrepignore` replaces the built-in default, so it must restate it. |
| 19 | 2026-11-07 13:10 | The canary step uses `git grep -l -F -e` (file names) and `git log -S` (commit ids) and never echoes the value; it also scans history; it skips when the secret is absent (fork PRs). | R-LEAK-1: a leak check must not itself leak. History matters because a leaked canary stays in a public repo's history. |
| 20 | 2026-11-07 13:10 | `pip-audit --skip-editable` (no `--strict`): the local editable `prm` isn't on PyPI; every installed dependency is still audited. gitleaks-action runs with PR comments off (the job token is read-only); findings still fail the step. | `--strict` turns the editable skip into an error. Comments would need `pull-requests: write`, which CI must not have. |
| 21 | 2026-11-07 13:10 | Docker image installs only `prm/` + `prm.server.toml` (`PRM_SERVER_CONFIG=/app/prm.server.toml`), runs as a non-root user, keeps state on `/data`; `.dockerignore` excludes `.env*` (except `.env.example`), `.league/`, `.prm-cache/`, `*.db`, `.git`, and `examples/`/`tests/`/tooling. CI runs `docker build`. | The factory never imports `examples/`, and fixture holdouts have no business in a server image. Secrets come from the platform env at run time only. |
| 22 | 2026-11-07 13:40 | `scripts/guard.py` (PreToolUse, R-HAR-2): **unparseable stdin exits 0** silently, but **an internal error exits 2** (fail closed). | Claude Code always sends valid JSON, so garbage input has nothing to judge and blocking it would brick the session. A crash on a real payload, though, could be triggered on purpose to slip a call past the guard, so it blocks. |
| 23 | 2026-11-07 13:40 | The guard path-checks commands and code, **not prose**: commit messages / PR bodies (`-m`, `--body`, ...), `echo`, and text written with `cat > file <<EOF` aren't scanned for `.league`/`.env`/holdouts paths; heredocs fed to interpreters and `python -c` are, and mentioning a `*_TOKEN`/`*_SECRET`/`*_API_KEY` name in inline code blocks. `$NAME` expansions of those block everywhere. Grep's `pattern` is a content regex and isn't path-checked (its `path`/`glob` are). | Agents write about holdouts and `.env` all day in docs and commits. Blocking that would push people to turn the hook off. Reading or expanding a secret is the real risk. |
| 24 | 2026-11-07 13:40 | A `*holdouts*` **file ending in `.py`** isn't a holdouts path (`prm/settle/holdouts.py`, `tests/settle/test_holdouts.py`). Any holdouts directory, archive or glob outside `examples/` is blocked. The guard also protects `.semgrepignore`, `~/.claude/settings*.json` and the hook scripts themselves. | WP D owns those source files. Editing `.semgrepignore` or a guard script would weaken the scan or the guard, which counts as "editing CI, semgrep or hook config". |
| 25 | 2026-11-07 14:10 | The guard hook catches the obvious and accidental cases only (now also globs/brace expansion, split strings in inline code, emptying/reverting tests, `-m "not ..."`, credential stores, the keychain). Indirection through script files, obfuscated code, and weakening a test via Edit/Write are documented as known limits, not chased. | A regex hook can't tell a weakened test from a legit test edit. The real enforcement for test weakening is CI plus review. For holdouts, it's that they live in a private repo the coding agents never get a token for. |
| 26 | 2026-11-07 13:56 | **The oracle is the post-merge outcome.** A merged PR settles **NO** if, within N days (default 14), it is reverted or a later fix commit touches lines it added; otherwise **YES** at day N. NO settles the moment it is observed. Supersedes "settle every market on the holdouts" in #5. | If the settlement check can be run at decision time, you don't need a market: just run the check. Post-merge outcomes don't exist when we gate, so the price is new information, and settlement needs no human. |
| 27 | 2026-11-07 13:56 | **Rejected PRs never settle.** A blocked or no-consensus market is VOID and every trader's spend is refunded. NO bets only pay on merged PRs that later get reverted/fixed. | Unmerged code has no post-merge outcome. Known cost, accepted for now: blocking is free (a lone bearish trader can hold the price under the reject line at no risk), which biases toward false rejects. The league measures the false-reject rate. |
| 28 | 2026-11-07 13:56 | **Escalation replaces the human-review band.** `p ≥ A` → merge; `p < B` → reject; in between → an escalation round: each trader sees the others' rationales, re-estimates (one more LLM call) and trades again. Up to `max_escalations` (default 2); still in between → reject "no consensus" (fail closed). Spend caps stay cumulative across all rounds. Config: `[gate].human_review` is read as B until renamed; `[market].max_escalations` is new (WP A). | The goal is no human review. Extra compute only where the market is uncertain; the decision still comes from bankroll-weighted trades, and cumulative caps keep R-MKT-3. Known risk, accepted for now: LLM herding in debate. |
| 29 | 2026-11-07 13:56 | **Hackathon stand-in: the holdouts play the post-merge oracle** in the league and the live demo (fails the holdouts = would have been reverted). Merged markets pay out on the holdout result; rejected markets are refunded per #27 but still run the holdouts as an **unpaid check** ("market right/wrong"), so Brier/calibration score every market. A real post-merge settler (revert detection) is P1. | We can't wait 14 days on stage, and WP C/D's holdout settlement is already in flight, so nothing built so far is thrown away. |
| 30 | 2026-11-07 12:53 | LMSR prices are clamped to `[1e-9, 1 - 1e-9]`, and `budget_trade` caps the reported cost at `spend` (absorbs ~1e-15 float rounding). | A market can never sit at exactly 0 or 1 (logit would blow up), and "never spends more than the cap" holds exactly, not just within tolerance. |
| 31 | 2026-11-07 12:53 | `positions` gets two columns beyond PLAN §5: `cap` (the per-market spend cap, fixed from the bankroll when the position opens) and `payout` (set once at settlement). | The cap must be "of bankroll at open" even while other markets move the bankroll; a stored payout lets a repeated settle return the same result without paying again. |
| 32 | 2026-11-07 12:53 | `events` is append-only at two layers: an ORM `before_update`/`before_delete` listener raises `AppendOnlyError`, and on SQLite `BEFORE UPDATE/DELETE` triggers abort raw SQL too. | The audit log is evidence; a law that only holds for well-behaved callers isn't one. |
| 33 | 2026-11-07 13:50 | **Optimistic locking** on `markets`, `traders`, `positions` (`version_id` + SQLAlchemy `version_id_col`), and **`markets.attempt`** (default 1) joins the idempotency key (repo_id, pr_number, head_sha, source, attempt). WP E/G: a VOID market for the same PR/sha is retried as attempt + 1 (max 3); a stale write raises `StaleDataError` and rolls back the whole transaction. | Code review found a double-settle race and lost bankroll updates under concurrent requests; and a VOID market must not permanently block a redelivered/reopened webhook from getting a fresh market. |
| 34 | 2026-11-07 12:57 | **A↔B contract:** `prm.market.engine.BeliefProvider` is a Protocol with one method, `async get_belief(spec: TraderSpec, bundle: PRBundle) -> BeliefResult`. The engine gathers all traders in parallel; any exception (or a non-`BeliefResult`) becomes an abstaining belief whose error is just the exception type. | WP B can build real/fake/replay providers without touching the engine, and a misbehaving trader can never crash the market or leak an exception message (which might carry request data) into the DB. |
| 35 | 2026-11-07 12:57 | Engine fail-closed policy: an unexpected exception inside a step VOIDs the market (refund, gate `failure`) and re-raises; `gate()` instead returns the failure decision. Caller mistakes (`IllegalAction`, `IllegalTransition`, `TradeRejected`, `MarketNotFound`) raise **without** voiding. | A judge betting a second late must get a 409, not void a live market; a real fault must never leave a market able to gate `success`. |
| 36 | 2026-11-07 12:57 | Engine details: `settle()` on a SETTLED market returns the stored payouts and pays nothing (on VOID it returns `{}`); `gate()` on a VOID market returns the failure decision; `markets.latency_ms` is the **max** belief latency (beliefs run in parallel, so that's the wall time), `cost_usd` the sum; human trades spend exactly `spend`, are logged as round 0, and trade events go to `events` with `from_state == to_state` and actor = trader name. | Retried settlement webhooks are safe; the pipeline always has a gate to post; latency reflects what users wait. |
| 37 | 2026-11-07 13:55 | **Corrects #35/#36 after code review.** (a) `human_trade` no longer runs under the fail-closed wrapper: on any error its transaction rolls back and the error propagates (a stale/duplicate write becomes `TradeConflict`, API 409); a judge's request can never void a live market. (b) `gate()` is idempotent: GATED/SETTLING/SETTLED return the stored decision, VOID the failure decision, and an unexpected error returns `failure` even if voiding also fails (one `_fail_closed` helper, `reraise=False`). (c) Each belief is bounded by `asyncio.wait_for` (engine kwarg `belief_timeout_s`, default 150 s = 45 s x 3 LLM attempts); a timeout abstains with error `TimeoutError`. (d) `settle`/`void`/the agent trading transaction re-read and retry up to 3 times on `StaleDataError`, so a lost settle race returns the stored payouts. (e) `create()` returns the latest non-VOID market for the key, else opens attempt + 1, and raises `MarketAttemptsExhausted` after 3. | Review found a double-settle race, lost bankroll updates, a non-idempotent gate that the pipeline would turn into a VOID, an unbounded gather, and VOID markets blocking re-creation. |
| 38 | 2026-11-07 13:10 | The sample target's **visible unit tests are deliberately partial**: they don't cover unauthenticated `DELETE` or the title max length. | That is what the demo bug patches break, so a buggy PR passes the author's own tests and only the hidden holdouts catch it, which is the realistic case the factory exists for. |
| 39 | 2026-11-07 13:10 | The sample target is a **standalone mini-repo**: package `notes_app` at its root, its own `pytest.ini` (`pythonpath = .`), imported via `PYTHONPATH={head}`. | It behaves like a real target repo, so the same `.prm.toml` works locally and in settlement; the factory's `testpaths = ["tests"]` keeps it out of `make test`. |
