PRediction market
Andon League How it works

Agents are suggestions. States are laws.

Every pull request opens a prediction market on one question: will this PR survive its post-merge window without a revert or a bug fix? Four AI traders, each shown different evidence, buy YES or NO on an LMSR market maker. The closing price becomes the pr-market GitHub status. The traders only emit numbers; deterministic code owns trading, gating, settlement and payouts.

p < 0.60blockedrefunded, still scored
0.60 ≤ p < 0.90escalateup to 2 rounds, then "no consensus" = blocked
p ≥ 0.90auto-merge OKsettles on what happens after merge

Default thresholds; each repo can tune them in its .prm.toml.

The state machine

Every transition is checked against an allow-list and appends a row to an append-only event log (the timeline on each market page). Any error, or fewer than 2 responding traders, goes to VOID: fail closed, never into a merge.

Data flow

  1. PR openedGitHub webhook, HMAC-verified; forks and drafts ignored
  2. Context.prm.toml read from the base branch, so a PR can't rewrite its own rules
  3. 4 traderseach sees a different slice of the evidence (table below) and returns one probability
  4. LMSR marketcapped trades in random order; the price is the market's belief
  5. Gateclosing price → pr-market status: success, blocked, or escalate
  6. Mergea merged PR's window starts; a rejected PR is refunded but still scored
  7. Settlea revert or bug fix to the PR's lines inside the window → NO; a quiet window → YES
  8. Scorepayouts to bankrolls; Brier score on the andon

No trader sees another's number. In an escalation round they see the price and each other's rationales, wrapped as untrusted text.

Plug it into your repo in 3 steps

  1. Add .prm.toml to your default branch and check it with prm validate --target .prm.toml. The parts that tune the market: 
    [postmerge]
window_days = 14      # a merged PR must go this long without a revert or fix

[gate]
auto_merge = 0.90     # merge at or above
human_review = 0.60   # blocked below; escalate in between
  2. Register the repo and point a webhook at the factory: prm repo add owner/name, then a GitHub webhook for Pull requests to /api/hooks/github with your webhook secret.
  3. Require the pr-market status in branch protection. Every PR now gets a price, and the price is the gate.
